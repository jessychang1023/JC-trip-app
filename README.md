# 旅程手帳 設定說明

這份說明帶你完成兩件事：雲端同步（Firebase）和憑證上傳到自己的 Google Drive。兩者都可以先不設定，App 會自動隱藏對應功能，照常當作單機版使用。

## 檔案清單（全部上傳到 GitHub 儲存庫最上層）

index.html、firebase-config.js、sw.js、manifest.webmanifest、icon.svg、icon-192.png、icon-512.png

以後只需要修改 firebase-config.js，其他檔案不用動。

## 一、雲端同步（Firebase）

1. 到 https://console.firebase.google.com 按「新增專案」，名稱自訂，Google Analytics 可以關閉。
2. 進入專案首頁，按「網頁」圖示（`</>`）註冊應用程式，暱稱隨意，不需要勾選 Firebase Hosting。
3. 畫面會顯示一段 `firebaseConfig`，把 apiKey、authDomain、projectId、appId 等值，填進 firebase-config.js 對應的位置。
4. 左側選「建構」→「Firestore Database」→「建立資料庫」，位置選 asia-east1（台灣），模式選「正式版模式」。
5. 進入 Firestore 的「規則」分頁，整段換成下面的規則，按「發布」。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/{code} {
      allow get, write: if true;
      match /{sub=**} {
        allow read, write: if true;
      }
    }
  }
}
```

這組規則的意思：沒有人能列出所有旅程，只有知道完整旅程代碼的人才能讀寫那一趟旅程。旅程代碼是 12 位隨機字元，請只分享給同行者。

6. 把更新後的 firebase-config.js 上傳到 GitHub 覆蓋舊檔。

## 二、憑證上傳到 Google Drive

可以直接使用上面的同一個 Google Cloud 專案（Firebase 專案本身就是 Google Cloud 專案）。

1. 到 https://console.cloud.google.com ，選擇同一個專案。
2. 「API 和服務」→「程式庫」，搜尋並啟用「Google Drive API」。
3. 「OAuth 同意畫面」（新版叫「Google Auth Platform」）：使用者類型選「外部」，填入應用程式名稱和你的電子郵件。範圍加入 `.../auth/drive.file`。
4. 在「測試使用者」加入要上傳憑證的人的 Gmail，包含你自己和同行者。測試中的應用程式只有名單內的人能登入。
5. 「憑證」→「建立憑證」→「OAuth 用戶端 ID」→ 類型選「網頁應用程式」。在「已授權的 JavaScript 來源」填 `https://你的帳號.github.io`（只填網域，不要加 /travel-app/）。
6. 複製產生的用戶端 ID，填進 firebase-config.js 的 `GOOGLE_CLIENT_ID`，再上傳覆蓋。

各主控台的介面名稱可能略有不同，找對應的項目即可。

### 出現「Google 尚未開放權限／存取遭封鎖／未驗證」怎麼辦

這是 Google Cloud 的 OAuth 同意畫面還在「測試中」，只有名單內的帳號能授權。兩種解法擇一：

1. **把自己和同行者加入測試使用者**：Google Auth Platform →「目標對象」（舊版：OAuth 同意畫面）→「測試使用者」→ 新增 Gmail。這是最保險的做法，但測試中的授權每 7 天會過期，過期後要重新授權。
2. **發布到正式版**：同一頁按「發布應用程式」。本 App 只用 `drive.file` 這個範圍（只能存取 App 自己建立的檔案，屬於非敏感範圍），不需要送 Google 審查。發布後任何 Gmail 都能授權，畫面可能出現「Google 尚未驗證這個應用程式」，按「進階」→「前往…（不安全）」即可。

如果畫面出現的是 400 invalid_request，請確認建立用戶端 ID 時**沒有**勾選「用於 AI 代理程式」，並用一般瀏覽器分頁開啟網址（不要用 LINE 或 Facebook 內建瀏覽器）。

**上傳失敗也能儲存**：憑證表單的文字（名稱、訂位代號、備註）一定會先存好，只有截圖檔案沒上傳成功時會提示，之後按「編輯」重新選檔案即可。上傳中按「取消」會放棄這次儲存。

## 三、用 Excel 或 CSV 匯入行程

1. 用「行程匯入範本.xlsx」（或 App 內「下載 CSV 範本」）填好行程。必填欄位只有「日期」和「名稱」。
2. 在 App 的「工具」分頁按「選擇 Excel／CSV 檔案」，選擇檔案。
3. 確認畫面顯示的筆數後按「匯入」，項目會加到目前選取的旅程。
4. 重複匯入同一份檔案不會產生重複項目。日期超出旅程範圍時，旅程日期會自動延長。
5. 匯入 .xlsx／.xls 檔時需要連上網路；CSV 不需要。

### 從 Google 工作表匯入

1. 在 Google 工作表按右上角「共用」，把一般存取權改成「知道連結的任何人」、角色「檢視者」。
2. 複製網址，貼到 App「工具」分頁的「Google 工作表連結」，按「從 Google 工作表匯入」。網址會記在這個裝置上，下次不用再貼。
3. 之後在 Google 工作表修改行程，回 App 再按一次匯入即可。已匯入過的項目不會重複，但在工作表改過內容的項目會被當成新項目加入，舊項目需要手動刪除。
4. 可辨識的欄位標題：日期（或「日期與主題」）、時間、類型、行程內容與景點說明（或「名稱」）、推薦交通方式、推薦店家/地點（或「地點」）、備註、預算（或「預估費用」）、幣別。第一列必須是標題列。
5. 「日期與主題」欄可寫成「10/20（二）抵達東京」、「Day 2｜10/21 澀谷原宿」、「2026-10-22」等，App 會取出日期，剩下的文字當作當天主題，放進當天第一個項目的備註。
6. 日期欄空白的列會沿用上一列的日期，所以合併儲存格也能使用。
7. 推薦交通方式會寫進備註（前面加「交通：」），行程內容太長時，完整文字也會放進備註。
8. 幣別可寫 JPY、日圓、日幣、台幣、NT$ 等，空白時使用旅程的主要幣別。

**如果工作表不想公開**：可以改用 Google 登入授權讀取，需要額外設定。
- 在 Google Cloud 同一個專案啟用「Google Sheets API」。
- 在 OAuth 同意畫面新增範圍 `https://www.googleapis.com/auth/spreadsheets.readonly`。
- 設定好後，App 會在無法直接讀取時，改跳出 Google 授權視窗，用你自己的帳號讀取。這個帳號必須有該工作表的檢視權限，也要在測試使用者名單內。

**如果匯入失敗**：先確認共用設定是「知道連結的任何人」。仍然失敗時，在 Google 工作表按「檔案 → 分享 → 發布到網路」，連結選「逗號分隔值 (.csv)」，把產生的連結貼進 App。

**匯入到哪一趟旅程**：項目會加進目前選取的旅程。如果工作表日期和旅程相差超過 60 天，App 會要你先新增一趟新的旅程。

已經有行程文字，想快速轉成表格？可以把行程貼給 Claude，請它「整理成日期、時間、類型、名稱、地點、備註、預估費用、幣別的表格」，再貼進 Excel 存檔。

## 四、使用方式

- **全日路線**：行程分頁右上角的「全日路線」會開出選單。「步行」和「開車」是一整天一條路線（含中途停靠，一次最多 11 個地點，超過會自動分段）；「大眾運輸」是一段一段的連結，因為 Google 地圖的大眾運輸模式不支援中途停靠點。只有填了「地點」的項目才會列入，連續相同的地點只算一次。
- **購物清單**：底部「購物」分頁。每項可填預計單價、幣別、數量、買給誰、店家／地點（可開地圖）。上方會用主要幣別加總「預計花費、已買、還沒買」。勾選「已購買時同時記入花費」會自動新增一筆「購物」花費到預算分頁，不會重複記帳。購物清單和其他資料一樣會同步給同行者。

- 在「工具」分頁按「開啟雲端同步」，會產生旅程代碼。按「複製邀請連結」傳給同行者，對方打開連結、輸入名稱就能加入。
- 憑證截圖會上傳到上傳者自己 Google Drive 的「旅程手帳」資料夾。每份憑證可選「僅自己可見」或「知道連結的人可檢視」，同行者只會在你選擇分享時看到「開啟檔案」。
- 訂位代號、備註等文字欄位會同步給所有知道旅程代碼的人，護照號碼等私密內容請不要填在文字欄位。
- 沒有網路時仍可查看與修改，連線後自動同步。第一次使用同步功能時需要先連網一次，讓 App 把雲端元件存到裝置上。
- 出國前請在 Google Drive App 把重要憑證檔案設為「離線可用」，否則沒網路時打不開檔案。
